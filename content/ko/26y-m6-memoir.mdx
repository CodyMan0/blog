## 들어가며

5월 말에 예고했던 6월 계획은 이랬다.

- **앱 마이그레이션** : Flutter에서 React Native로. 이전 웹 마이그레이션과는 조금 다르게 진행 시도
- **백엔드 기초 학습** : 미오 경험 기반 DB 정규화 / Nest.js > Express > Node 동작 원리 / 패키지 매니저·모노레포 (6월 초 모노레포 등장)
- (5월 인터뷰 후속으로) **의료기기 다나와 페이지 전면 개편 + 앱 추가**

그런데 6월은 계획 밖의 일도 많았다. 실제로 6월에 한 일:

1. **Amplify → Vercel 대이관** — 인프라 전면 이관
2. **네이버 지도 API 장애 후속 대응** — 장애 이후 재발 방지까지
3. **SEO 개선 (png → html)** — 이미지로 박혀 있던 텍스트를 마크업으로
4. **미팅 주도** — 크고 작은 미팅을 직접 이끈 경험

> 먼저 각 항목에 한 줄씩만: 했다 / 못 했다 / 달라졌다. 그다음 아래 섹션에서 풀어쓰기.

---

## 1. Flutter → React Native 앱 마이그레이션

> **채우기 가이드** (다 지우고 편하게)
> - 웹 마이그레이션과 "다르게 진행 시도"한다고 했는데 실제로 뭘 다르게 했나? (작업 쪼개는 방식? AI에게 시키는 방식? 점진 vs 한 번에?)
> - 어디까지 진행됐나 (범위, 배포 여부)
> - 웹 마이그레이션 경험이 실제로 도움이 됐나 / 앱이라서 예상 못 한 차이는?

---

## 2. 백엔드 기초 학습 — 미오가 남긴 숙제

> **채우기 가이드**
> - 계획했던 것: DB 정규화, Nest > Express > Node 동작 원리, 패키지 매니저·모노레포
> - 실제로 뭘 어떻게 공부했나? (강의? 책? 실무 모노레포에 바로 적용?)
> - 6월 초 등장한 모노레포 — 실무에서 어떤 상황이었고 공부가 어떻게 연결됐나
> - 못 한 게 있다면 왜 못 했는지 — 그것도 훌륭한 기록

---

## 3. 의료기기 다나와 전면 개편

> **채우기 가이드**
> - 5월 의사 인터뷰에서 발견한 것들이 개편에 어떻게 반영됐나 — "인터뷰 → 제품 변경"의 연결고리가 이 글의 백미
> - 앱 추가는 진행됐나
> - 수치가 있으면 최고 (등록 수, 상담 수, 페이지 유입 등 — 앰플리튜드 볼 겸 같이 찾아봐도 좋음)

---

## 4. Amplify → Vercel 대이관

> **개요**
> - 왜 옮겼나 — 비용 / 개발 경험(DX) / 프리뷰 배포 / 빌드 속도 중 무엇이 결정적이었나
> - 무엇을 옮겼나 — 앱, 환경변수, 도메인, CI/CD 파이프라인
> - 이관 중 겪은 이슈와 해결 (다운타임은? 롤백 계획은?)
> - 결과 — 옮기고 나서 실제로 뭐가 좋아졌나 (수치 있으면 최고)

---

## 5. 네이버 지도 API 장애 후속 대응

> **개요**
> - 무슨 장애였나 — 증상과 원인 (지도가 안 뜸? 쿼터 초과? 스펙 변경?)
> - 사용자 영향 — 어떤 화면/기능이 얼마나 영향받았나
> - 즉시 대응 + 재발 방지 — 폴백 / 대체 수단 / 모니터링·알림
> - 배운 것 — 외부 API 의존의 리스크를 어떻게 다루기로 했나

---

## 6. SEO 개선 — png를 html로

> **개요**
> - 왜 문제였나 — 이미지로 박힌 텍스트는 크롤링·접근성·CWV에서 손해
> - 어떻게 바꿨나 — 이미지 → 시맨틱 마크업/텍스트로 전환한 범위
> - 기대 효과 — 색인, 접근성, 로딩 성능 (이전 SEO 작업들과의 연결)

## 7. 미팅을 주도하며

> **개요**
> - 어떤 미팅들을 주도했나 — 배경과 목적
> - 왜 내가 이끌게 됐나 — 개발자가 미팅을 주도한 맥락
> - 진행 방식 — 어떻게 준비하고 합의를 이끌었나
> - 남은 것 — 미오에서 배운 "의사소통"이 여기서 어떻게 이어졌나
