> 초안. 데스크탑에서 대화하며 채운다.

## 이력서에 쓸 만한 것

- 지도 관련 PR **64건** — 렌더링 최적화, 클러스터링, 드릴다운 줌, 반경/폴리곤 스코프

## 실제로 한 일

네이버 지도 위에 의원·매물·리포트 핀을 얹는다. 데이터가 늘면서 이동할 때마다 렉이 걸렸고, 렌더링 방식과 갱신 시점을 여러 번 갈아엎었다. 최근에는 클릭 대상에 따라 줌 레벨과 분석 범위(건물 단위 / 500m 반경)를 다르게 잡는 일을 했다.

## 예상 꼬리 질문

1. **마커가 몇 개일 때 뭐가 느려졌나.** 렌더링인가, 데이터 페칭인가, 이벤트 핸들러인가. 어떻게 특정했나.
2. 최적화 **전후 수치**는? (프레임, 입력 지연, 렌더 횟수)
3. 클러스터링을 직접 구현했나 라이브러리인가. **좌표를 어떻게 묶나** — 격자? 거리 기반? quadtree?
4. 지도 이동마다 서버를 부르나. **뷰포트 기준 쿼리**는 어떻게 짰나. 디바운스 기준값은 왜 그 숫자인가.
5. 목록·카운트·지도 세 군데의 **결과가 어긋나지 않게** 어떻게 맞췄나. (radius / polygon 스코프)
6. 핀 라벨 거리 기반 표시 — 겹침 판정을 매 프레임 하나? 비용은?
7. React 리렌더와 지도 SDK의 명령형 API를 어떻게 섞었나. ref? 외부 스토어?

## 확인 필요

- 최적화 전후 실제 측정치 (없으면 지금이라도 재현해서 측정)
- 마커 최대 개수, 데이터 소스

## 파볼 층

- 1층: 마커를 언제 다시 그리나 (React 렌더 ↔ 지도 SDK)
- 2층: **공간 인덱싱** — 좌표를 묶는 자료구조 (격자 / geohash / quadtree)
