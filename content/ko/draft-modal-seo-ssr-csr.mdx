> 초안. 데스크탑에서 대화하며 채운다.

## 문제 발견 — 검색 결과가 이상했다

이벤트 모달을 새로 넣은 뒤, 오픈닥터를 검색했을 때 결과 스니펫이 이상하게 나왔다. 병원 상세 페이지라면 병원 이름과 상세 설명이 보여야 하는데, 검색 결과에는 모달에 있는 "닫기", "오늘 그만 보기" 같은 문구가 노출됐다. 사용자가 실제로 검색해서 들어오는 유입 화면이 팝업 버튼 텍스트로 채워진 셈이었다.

원하는 모습은 분명했다. 병원 상세 페이지는 병원 이름과 상세 설명이 검색 결과에 등장해야 했다.

## 당시 구현 방식

문제를 이해하려면 모달이 어떻게 붙어 있었는지부터 봐야 했다. 구현은 두 단계로 나뉘어 있었다.

1. SSR 단계: Next.js 최상위 `layout.tsx`에서 모달 API를 통신해 데이터를 받아 `EventModal`로 내려줬다.
2. CSR 단계: `EventModal` 내부에 링크와 이미지, 그리고 "오늘 그만 보기 / 닫기"가 들어 있었다.

모달은 클라이언트에서 열고 닫는 컴포넌트였지만, 그 컴포넌트가 최상위 레이아웃에 얹혀 있었다는 게 핵심이었다.

## 원인 — SSR과 CSR이 만나는 지점

문제가 어디서 나는지 후보를 세워 봤다. SSR인가, CSR인가, 아니면 전체 페이지 로드 시점인가.

파고 보니 원인은 SSR과 CSR이 만나는 지점에 있었다. 클라이언트 컴포넌트인 `EventModal`이라 해도, 그 초기 HTML은 서버에서 렌더링되어 풀 페이지(full-page) HTML에 포함된다. 크롤러는 자바스크립트로 모달이 열리고 닫히는 상호작용을 보는 게 아니라, 서버가 내려준 그 초기 HTML을 읽는다. 그래서 최상위 레이아웃에 심어 둔 모달의 텍스트가 모든 페이지의 인덱싱 대상 HTML 안으로 딸려 들어갔고, 검색 결과에 "닫기 / 오늘 그만 보기"가 병원 상세 설명 자리를 차지한 것이다.

```
layout.tsx (SSR)
   └─ EventModal (client component)
        └─ 초기 HTML은 서버가 렌더 → full-page HTML에 포함
              └─ 크롤러가 이 HTML을 읽음
                    └─ 검색 결과에 "닫기 / 오늘 그만 보기" 노출
```

"클라이언트 컴포넌트니까 서버와는 무관하다"는 감각이 함정이었다. 클라이언트 컴포넌트도 초기 HTML은 서버가 그려서 내려보낸다는 사실을 놓치면, 이렇게 눈에 보이지 않는 곳에서 새어 나간다.

## 해결 — 급한 불부터, 그다음 정석

18일 배포에서는 우선 급한 불을 껐다. dynamic 방식을 활용해 모달이 클라이언트에서만 적용되도록 설정했다. 서버가 그리는 초기 HTML에서 모달을 빼내면, 인덱싱 대상 HTML에 모달 텍스트가 들어가지 않는다.

다음 날인 19일, Next.js 공식 문서를 다시 읽으면서 이 문제를 더 정확하게 푸는 다른 방식이 있다는 걸 알게 됐다. 정석에 해당하는 이 방법은 문서를 근거로 다시 정리해 채울 자리로 남겨 둔다. 급한 배포 때 넣은 dynamic 처리와, 문서가 권하는 방식이 어떻게 다른지를 나란히 두는 게 이 글의 마무리가 될 것이다.

## 마무리 — 클라이언트 컴포넌트도 서버가 한 번 그린다

증상은 SEO였지만, 원인은 렌더링 경계에 대한 오해였다. 클라이언트 컴포넌트라는 이름 때문에 "서버와 상관없다"고 생각했는데, 실제로는 초기 HTML을 서버가 그려 풀 페이지에 담아 내려보낸다. 최상위 레이아웃처럼 모든 페이지에 공유되는 자리에 그런 컴포넌트를 두면, 그 안의 텍스트가 전 페이지의 인덱싱 결과에 영향을 준다. SSR과 CSR이 만나는 지점을 눈에 그릴 수 있어야, 이런 문제를 배포 전에 미리 잡을 수 있겠다고 느꼈다.
