# PRD: 뷰티 브랜드 언급 모니터링 서비스

## 1. 개요

뷰티 브랜드(1~5인 소형 기업)를 위한 네이버 블로그 + 유튜브 자사 브랜드 언급 자동 모니터링 서비스. 매일 키워드 기반으로 신규 언급을 수집하고, 오전 9시에 리포트를 발송한다.

---

## 2. 왜 필요한가

- **언급 = 바이럴의 시작.** 자사몰 트래픽 급증의 원인은 대부분 외부 인플루언서
- 시딩은 월 수백~수천건 발생하지만, **실제 포스팅 여부를 확인할 방법이 없음**
- 정식 콜라보는 비싸고, 시딩으로 바이럴이 터지면 비용 대비 효과 극대화
- 회사 소개서/IR 자료 만들 때마다 언급 사례를 일일이 찾아야 하는 번거로움

---

## 3. 시장 분석

### 기존 플레이어

| 서비스 | 핵심 기능 | 한계 |
|--------|----------|------|
| 피처링 | 인플루언서 검색/분석, 캠페인 관리 | 대형 브랜드 타겟. 비쌈. 자체 플랫폼 내 캠페인만 추적 |
| 퍼핀 | 시딩 올인원 (발굴→캠페인→성과) | SaaS 구독. 자체 플랫폼 통해 시딩한 건만 추적 |
| 태그바이 | 무제한 체험단 모집 | 모집 특화. 포스팅 모니터링 기능 없음 |
| 달파 | AI 경쟁사 가격/리뷰 분석 | 범용 솔루션. 시딩 특화 아님 |

### 시장의 빈틈

```
[시딩 전]                     [시딩 후]
인플루언서 찾기 → 시딩 발송 → 포스팅 확인 → 성과 분석
 피처링/퍼핀      태그바이       ← 여기 비어있음 →
```

- 기존 서비스는 **"시딩 전"** (인플루언서 찾기)에 집중
- **"시딩 후 포스팅 확인"** 구간에 전문 서비스가 없음
- 플랫폼 밖에서 일어나는 시딩(DM, 오프라인)은 아무도 추적 안 함

### 우리 포지셔닝

| 비교 | 피처링/퍼핀 | 우리 서비스 |
|------|-----------|------------|
| 타겟 | 대형 브랜드 | 소형~중형 뷰티 브랜드 (1~5인) |
| 핵심 | 인플루언서 검색 | 시딩 후 포스팅 모니터링 |
| 가격 | 영업 문의 (비쌈) | 월 10~30만원 |
| 단계 | 시딩 전 | **시딩 후** |

---

## 4. 페르소나

**뷰티 브랜드 대표 (1~5인 기업)**

- 매달 수십~수백건 시딩을 보냄
- 마케팅 전담 인력이 없거나 인턴이 담당
- 매일 아침 네이버/유튜브에서 브랜드명 수동 검색
- 시딩 보낸 인플루언서가 실제 포스팅했는지 하나씩 확인
- 포스팅 된 시점을 모르기 때문에 대응이 늦음
- 회사 소개서/바이어 미팅용 언급 사례를 수동으로 모음

---

## 5. 고객의 현재 행동 (As-Is)

1. 매일 유튜브/네이버에 자사 브랜드명 수동 검색
2. 시딩 보낸 인플루언서별로 포스팅 여부 하나씩 확인
3. 언제 올라왔는지 모르니까 매일 반복
4. 바이럴 터져도 감지 늦어서 기회 놓침
5. IR/소개서 만들 때 과거 언급 사례를 다시 찾아야 함

---

## 6. 해결하는 페인포인트

| # | 페인포인트 | 해결 방식 |
|---|----------|----------|
| 1 | 포스팅 확인 불가 — 시딩 후 올렸는지 수동 확인 | 키워드 기반 자동 수집 + 알림 |
| 2 | 수동 검색 반복 — 매일 플랫폼별 브랜드명 검색 노가다 | 크롤러가 매일 자동 수집 |
| 3 | 바이럴 감지 지연 — 터졌는데 모르고 지나감 | Daily 리포트로 신규 언급 즉시 파악 |
| 4 | 언급 아카이빙 — 소개서용 사례를 매번 찾아야 함 | 언급 DB 자동 축적 → 언제든 조회 |

## 7. 서비스 정의

### 인풋/아웃풋

| 항목 | 내용 |
|------|------|
| **인풋** | 브랜드명 / 모니터링 키워드 (고객이 등록) |
| **아웃풋** | 플랫폼별 신규 언급 횟수 + 링크 목록 |
| **알림 채널** | 이메일 (MVP) → 카카오 알림톡 (추후) |
| **갱신 주기** | Daily (매일 오전 9시) |

### 리포트 예시

```
📊 [브랜드명] 일간 모니터링 리포트 (2/18)

네이버 블로그: 3건 신규
  - "[브랜드명] 써봤는데 대박" — blog.naver.com/xxx (2/18)
  - "[브랜드명] 솔직 후기" — blog.naver.com/yyy (2/18)
  - "요즘 핫한 스킨케어 추천" — blog.naver.com/zzz (2/17)

유튜브: 1건 신규
  - "2월 뷰티 하울 🛍" — youtube.com/xxx (2/17)

총 언급: 이번 주 12건 (지난 주 대비 +4)
```

### MVP 범위

| 포함 | 제외 (추후) |
|------|------------|
| 네이버 블로그 모니터링 | 인스타그램 (API 제한) |
| 유튜브 모니터링 | 카카오 알림톡 |
| 이메일 리포트 발송 | 슬랙 연동 |
| 웹 대시보드 (언급 목록/검색) | 감성 분석 (긍정/부정) |
| 키워드 관리 | 경쟁사 비교 분석 |
| 언급 아카이빙 | PDF 리포트 내보내기 |

## 8. 기술 스택

### 아키텍처

```
Next.js (Vercel)
├── 웹 대시보드 — 로그인, 키워드 관리, 언급 목록 조회
├── API Routes — 크롤러 로직 (네이버 API + YouTube API)
├── Vercel Cron — 매일 새벽 수집, 오전 9시 알림 발송
└── Supabase — DB + Auth

알림: Resend (이메일) → 추후 카카오 알림톡
```

### 기술 선택 근거

| 선택 | 이유 |
|------|------|
| Next.js (App Router) | 주영님 주력 스택. 풀스택 가능 |
| Vercel | 인프라 관리 최소화. Cron 지원 |
| Supabase | DB + Auth 올인원. 무료 티어 충분 |
| Resend | 이메일 발송 API. 무료 티어 월 3,000건 |
| TanStack Query | 데이터 페칭/캐싱 (주영님 익숙) |
| TailwindCSS | UI 빠르게 구현 |

### 외부 API

| API | 용도 | 제한 |
|-----|------|------|
| 네이버 검색 API (blog.search) | 블로그 포스팅 메타데이터 수집 | 일 25,000건 / 검색당 최대 1,000건 |
| YouTube Data API v3 | 유튜브 영상 검색 | 일 10,000 단위 (검색 1회 = 100단위) |

### DB 스키마 (핵심)

```sql
-- 가입 고객
users (id, email, name, created_at)

-- 고객별 모니터링 키워드
keywords (id, user_id FK, keyword, platform, is_active, created_at)

-- 수집된 언급
mentions (id, keyword_id FK, platform, title, url, author, published_at, collected_at, view_count)

-- 알림 발송 이력
notifications (id, user_id FK, sent_at, mention_count, status)
```

### 크롤러 스케줄

| 시간 | 작업 |
|------|------|
| 매일 05:00 | 전체 키워드 크롤링 (네이버 + 유튜브) |
| 매일 09:00 | 신규 언급 리포트 이메일 발송 |

## 9. 기술적 제약 및 리스크

| 리스크 | 영향 | 대응 |
|--------|------|------|
| 네이버 검색당 1,000건 제한 | 인기 키워드면 데이터 잘릴 수 있음 | 타겟이 소형 브랜드 → 대부분 1,000건 이하. 날짜 범위 필터로 보완 |
| 유튜브 API quota 소진 | 고객 많아지면 하루 100회 검색 한계 | 초기엔 충분. 스케일 시 API 키 추가 or 검색 최적화 |
| 인스타그램 제외 | 고객이 가장 원하는 채널일 수 있음 | MVP에서 제외 명시. 추후 반자동(링크 입력→확인) 방식 검토 |
| Vercel Cron 실행 시간 제한 | Free 10초, Pro 300초 | 고객 수 적을 땐 충분. 스케일 시 별도 서버 분리 |

## 11. 서비스 플로우

### 사용자 플로우 (고객이 경험하는 흐름)

```
[가입] → [키워드 등록] → [매일 자동 수집] → [리포트 수신] → [대시보드 확인]
```

1. 가입/로그인 — 이메일 + 비밀번호 (Supabase Auth)
2. 온보딩 — 모니터링할 브랜드명/키워드 등록 + 플랫폼 선택 (네이버/유튜브/둘 다)
3. 대기 — "내일 오전 9시에 첫 리포트가 발송됩니다" (또는 즉시 1회 수집)
4. 리포트 수신 — 매일 오전 9시 이메일로 신규 언급 리포트 도착
5. 대시보드 — 전체 언급 목록 조회, 키워드별/플랫폼별 필터, 날짜 범위 검색, 즐겨찾기

### 시스템 플로우 (서버에서 일어나는 흐름)

```
[Cron 05:00] → [키워드 조회] → [API 호출] → [중복 체크] → [DB 저장]
                                                              ↓
[Cron 09:00] → [신규 언급 조회] → [리포트 생성] → [이메일 발송]
```

**매일 05:00 — 수집 프로세스**

1. DB에서 활성 키워드 전체 조회
2. 키워드별로 API 호출 (네이버 검색 API + YouTube Data API)
3. 기존 mentions 테이블과 URL 중복 체크
4. 신규 언급만 DB에 INSERT
5. 수집 로그 기록

**매일 09:00 — 알림 프로세스**

1. 유저별로 지난 24시간 신규 언급 조회
2. 신규 언급이 있는 유저만 필터
3. 리포트 HTML 생성 (키워드별, 플랫폼별 정리)
4. Resend API로 이메일 발송
5. notifications 테이블에 발송 이력 기록

## 15. 이메일 리포트 상세

### 구현 방식

- **React Email** + **Resend** 조합
- React 컴포넌트로 이메일 템플릿 작성 → Resend API로 발송

### 리포트 레이아웃

```
┌─────────────────────────────────────────┐
│  📊 [브랜드명] 일간 모니터링 리포트 (날짜)  │
│─────────────────────────────────────────│
│                                         │
│  네이버 블로그: N건 신규                   │
│  ─────────────────────                  │
│  • "포스팅 제목"              날짜  →링크  │
│  • "포스팅 제목"              날짜  →링크  │
│                                         │
│  유튜브: N건 신규                         │
│  ─────────────────────                  │
│  • "영상 제목"               날짜  →링크  │
│                                         │
│  총 언급: 이번 주 N건 (지난 주 대비 +N)     │
│                                         │
│  [대시보드에서 자세히 보기 →]               │
└─────────────────────────────────────────┘
```

### 기술 스택

| 도구 | 역할 |
|------|------|
| React Email | 이메일 템플릿을 React 컴포넌트로 작성 |
| Resend | 이메일 발송 API (무료 티어 월 3,000건) |
